## Five checkable stories and essential features

Every check below is **planned / not run**. Technical verification of this documentation is separate from usability results.

### S1 — Understand who the portfolio is for

**As an internship recruiter, I want a short introduction and opportunity goal so I can judge relevance.**

Essential features: name, BIS student context, student-level technical interests, opportunity goal, three project summaries and clearly labeled coursework.

**Check:** Show each page option to a peer without coaching. Ask who Seaf is, what opportunity he seeks and which project they would inspect first. Record their actual explanation. Pass if they identify the student context and proposed internship direction without mistaking coursework for employment. If unclear, revise the introduction and repeat with the reviewer.

### S2 — Inspect a project and personal contribution

**As a technical reviewer, I want a case study linked to its site, repository and checks so I can distinguish Seaf's work from the whole team's work and AI assistance.**

Essential features: three project entries (T-shirt, group business, portfolio), user/problem, two options, decision/reason, personal contribution, dated check evidence, limitations, live/source links and AI disclosure. Label group work as work in progress; do not imply its finished product is due at Portfolio Plan.

**Check:** From either option, ask a peer to open each project repository and identify one personal contribution and one recorded check. Verify the destination matches the project. A missing/duplicated/unconfirmed repository remains visibly pending; it does not pass merely because a link opens. No personal contribution can be credited from a proposed task assignment alone.

### S3 — Reach professional materials

**As a recruiter, I want Seaf's actual GitHub, LinkedIn and readable résumé so I can inspect his professional record.**

Essential features: labeled profile links, portfolio source link, three project-repository destinations and a résumé link plus an accessible text summary. Both page approaches expose these destinations.

**Check:** Open every final link in a signed-out browser. GitHub/LinkedIn must identify Seaf, not an example account. Résumé must render readable selectable text on desktop and a phone, without clipped content; its text summary must preserve the same facts. Pending materials stay plain status text, not fake or broken links. Inspect the public copy for approved contact information before publishing. A supplied private file is not automatically a public résumé URL.

### S4 — Navigate and choose a next step

**As a visitor using a phone or keyboard, I want clear navigation and an approved contact route so I can reach a project or professional material without getting lost.**

Essential features: visible focus, descriptive headings/link labels, skip link, responsive cards, readable contrast, and contact via an actual approved professional destination. No contact form or data collection is required.

**Check:** At 375px and desktop width, use only Tab/Shift+Tab/Enter to reach each project, résumé and profile control. Confirm focus remains visible, content does not overflow, and the contact action opens the approved destination without sending a message automatically. Record failures and retry fixes. Automated accessibility scans supplement this walkthrough, not replace it.

### S5 — Trace feedback into a decision and result

**As a class reviewer, I want linked feedback, a reasoned response and check evidence so I can see what changed and what remains open.**

Essential features: review request, real issue links, implement/investigate/defer/decline decisions with reasons, linked change commit/PR, dated observed verification and reviewer retry for accepted changes. Separate expected checks from actual results.

**Check:** Ask the reviewer to follow one real incoming issue through the decision, linked change/no-change rationale and verification. For an accepted change, obtain the reviewer's retry before closing the resolved issue. Missing feedback stays open with a next step; ask the instructor promptly to arrange a reviewer if needed. No feedback or result is invented to fill this story.

These are intended mechanisms, not measured hiring or conversion results. Keep résumé, profiles and project claims consistent and clearly distinguish personal, team and AI work.
