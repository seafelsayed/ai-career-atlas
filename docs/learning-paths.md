# Learning paths

These are suggested practice sequences, not certifications or promises of employment. Move at a pace that fits your starting point.

## If you already build software

1. Build a small model-powered feature with a clear user need.
2. Add a labeled evaluation set, compare a simple baseline, and analyze failures.
3. Add retrieval or tools only when the task requires them.
4. Deploy a pilot with logging, access controls, and a human review path.
5. Publish a case study covering quality, cost, latency, and limitations.

**Explore:** [Applied AI Engineer](/roles/applied-ai-engineer), [Forward Deployed Engineer](/roles/forward-deployed-engineer).

## If you enjoy analysis and careful testing

1. Learn enough Python to load data, run experiments, and produce reports.
2. Write a scoring rubric for a narrow AI task.
3. Collect representative examples and keep a separate test set.
4. Compare systems, document uncertainty, and investigate false positives and false negatives.
5. Publish a reproducible evaluation with versioned inputs.

**Explore:** [Evaluation Engineer](/roles/evaluation-engineer). Research engineering usually needs deeper ML and systems experience.

## If you come from operations or delivery

1. Map a workflow and identify a measurable problem.
2. Define a baseline and decide where human review is necessary.
3. Prototype a limited solution with an engineering partner.
4. Plan training, ownership, rollout, and escalation.
5. Compare pilot outcomes with the baseline and record what did not work.

**Explore:** [AI Deployment Manager](/roles/ai-deployment-manager). Architecture and FDE roles may require substantial software experience.

## A portfolio worth discussing

Include the problem, intended user, a working demonstration, your decisions, evaluation data, failure cases, and what you would improve next. Use synthetic or appropriately licensed data. A transparent small project is more useful evidence than an unexplained demo.
